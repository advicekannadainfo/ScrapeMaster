# Matching evidence coverage and release gates

Evidence baseline: `ce37989`. This is a scoped inventory of existing fixtures and
implemented gates, not a repeat architecture audit or a claim of universal support.
No new production defect was established, so no matching/parser code is changed.

## Measured coverage

`evidence-coverage.json` is generated by executing existing, unmodified fixtures
through the actual parsers. `tests/evidence-coverage.test.ts` checks reproducibility
and prevents missing categories from becoming passing cells. Run the stdout-only
reporter with `npx tsx --conditions=react-server scripts/report-evidence-coverage.mts`.
It performs no transport, database, refresh or comparison action.

- 18 category/store cells; only **3/18 (16.7%)** have captured Product API coverage.
- Three captured Product responses: Amazon fragrance 30ml, Flipkart fragrance 30ml,
  Myntra fragrance 100ml. All three source parsers pass price/stock/URL binding.
- Two additional documented examples: Flipkart monitor (tracking blocked by missing
  required identity/stock fields), Myntra jeans (source price parses, no independently
  selected clothing size emitted). Neither is a captured live response.
- All three Search fixtures are documented/synthetic contracts, **zero captured
  live Search responses**. They prove parser behavior, not search recall or the
  presence of an exact competitor in a real response.
- Reduced Product contract fixtures and synthetic standard-JSON-LD examples are
  not counted as additional independent captured responses.
- Electronics, fashion, grocery, appliances and books have no captured Product
  response coverage here. Existing synthetic safety tests do not change that fact.
- No category receives blanket release signoff. Fragrance has a conditional working
  vertical slice; the user's live Love Drunk/Old Money three-store success is separate
  user-reported evidence. Old Money has no captured full response in this inventory.

## Exact release gates

1. **Fragrance slice:** captured same-size source pairs across all three stores,
   including root selected-volume provenance, actual formulation/pack declarations
   and search payloads containing the matching candidates. Add absent/wrong-scent,
   20/30/100ml, EDP/EDT and null selected-quantity controls. Preserve the existing
   Love Drunk/Old Money live successes and offline regressions.
2. **Each additional category/store:** at least one actual sanitized successful
   main Product response and relevant Search response, plus a mismatched selected
   variant and missing-evidence control. Electronics needs subtype-specific gates
   (earbuds colour; phones RAM/storage; laptops CPU); fashion needs selected style,
   colour and size; grocery pack and quantity; appliances model/capacity; books
   checksum-valid ISBN, edition, language and binding. A single example is the
   minimum evidence to implement, not category-wide statistical validation.
3. **Persistence and UI:** validated selected facts survive JSON/BSON/Mongoose;
   saved-source and candidate observations remain URL/identity/price/stock bound
   and ≤10 minutes old. Identity links survive stale prices; stale prices do not.
   Define per-offer observation/legacy expiry semantics before claiming all retained
   customer-visible offers are fresh. No backfill or expiry behavior is changed here.
4. **Activation:** captured and synthetic regressions, symmetry, discovery/render
   consistency, wrong variants, manual preservation and unchanged request budgets
   pass before explicitly registering another canonical profile. Offline success
   never substitutes for Preview verification.
